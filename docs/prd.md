# PRD - Wi-Fi Auto Reconnect Agent (MVP)

# 1. 프로젝트 개요

## 프로젝트명

Wi-Fi Auto Reconnect Agent

## 목적

Windows 환경에서 백그라운드로 실행되는 Python 프로그램을 개발한다.

프로그램은 현재 Wi-Fi 연결 상태를 주기적으로 감시하고, Wi-Fi가 실제로 끊어진 경우에만 설정된 대상 SSID로 자동 재접속을 시도한다.

이미 어떤 Wi-Fi에든 정상 연결되어 있는 상태에서는 대상 SSID와 다르더라도 재접속을 시도하지 않는다.

---

# 2. 목표

이번 MVP는 다음 기능만 수행한다.

* 백그라운드 실행
* Wi-Fi 연결 상태 감시
* Wi-Fi 끊김 감지 시 자동 재접속
* 재접속 시도 및 결과 로그 기록

이번 버전에는 UI, Windows 서비스 등록, 강제 Wi-Fi 연결 해제 기능을 포함하지 않는다.

---

# 3. 핵심 동작 원칙

프로그램은 Wi-Fi 연결이 끊어진 경우에만 재접속 로직을 실행한다.

다음 상태에서는 재접속을 시도하지 않는다.

* Wi-Fi가 정상 연결된 상태
* 현재 연결된 SSID가 설정된 대상 SSID와 다른 상태
* 일시적으로 상태 확인이 불안정했지만 재확인 시 연결 상태로 확인된 경우

즉, 이 프로그램은 “항상 특정 SSID를 강제 유지하는 프로그램”이 아니라 “Wi-Fi가 끊겼을 때 지정된 SSID로 복구하는 프로그램”이다.

---

# 4. 동작 흐름

1. 프로그램 시작
2. 설정 파일 로드
3. 로그 시스템 초기화
4. 지정된 주기마다 Wi-Fi 연결 상태 확인
5. Wi-Fi가 연결되어 있으면 계속 감시
6. Wi-Fi가 끊어진 것으로 보이면 짧은 시간 후 재확인
7. 재확인 결과도 끊김이면 대상 SSID 검색
8. 대상 SSID가 발견되면 재접속 시도
9. 재접속 성공 또는 실패를 로그에 기록
10. 실패 시 설정된 간격과 횟수에 따라 재시도
11. 프로그램은 종료 신호를 받기 전까지 계속 실행

---

# 5. 기능 요구사항

## 5.1 Wi-Fi 상태 감시

프로그램은 Windows의 Wi-Fi 상태를 확인한다.

초기 MVP는 구현이 단순하고 안정적인 polling 방식을 사용한다.

기본 감시 주기:

* 5초

Wi-Fi 연결 상태 판단 기준:

* `netsh wlan show interfaces` 결과를 사용한다.
* `State` 값이 connected이면 연결 상태로 판단한다.
* `SSID` 값이 존재하는 경우에도 연결 상태로 판단한다.
* 연결 끊김으로 보이는 경우 1초 후 한 번 더 확인한다.
* 두 번 모두 끊김으로 판단될 때만 재접속 로직을 실행한다.

---

## 5.2 자동 재접속

Wi-Fi가 끊어진 경우에만 다음 절차를 수행한다.

1. 주변 Wi-Fi 목록 검색
2. 설정된 대상 SSID 존재 여부 확인
3. 대상 SSID가 발견되면 재접속 시도
4. 재접속 성공 여부 확인
5. 성공 또는 실패 결과 로그 기록

재접속 중 이미 Wi-Fi 연결이 복구된 경우:

* 재접속 루프를 즉시 중단한다.
* 불필요한 추가 재접속 시도를 하지 않는다.

연결 실패 시:

* 실패 로그를 기록한다.
* 설정된 재시도 간격 후 다시 시도한다.
* 최대 재시도 횟수는 설정 파일에서 관리한다.

---

## 5.3 설정

프로그램은 `config.json`에서 다음 값을 읽는다.

* 대상 SSID
* 감시 주기
* 재시도 간격
* 최대 재시도 횟수

예시:

```json
{
  "ssid": "SK_min5G",
  "check_interval": 5,
  "retry_interval": 5,
  "max_retry": 10
}
```

설정 값 검증:

* `ssid`는 비어 있지 않은 문자열이어야 한다.
* `check_interval`은 양의 정수여야 한다.
* `retry_interval`은 양의 정수여야 한다.
* `max_retry`는 양의 정수여야 한다.

---

## 5.4 로그

프로그램은 다음 이벤트를 기록한다.

* 프로그램 시작
* 프로그램 종료
* Wi-Fi 연결 끊김 감지
* 대상 SSID 검색 성공
* 대상 SSID 검색 실패
* 재접속 시도
* 재접속 성공
* 재접속 실패
* 이미 연결되어 있어 재접속 중단
* 예외 발생

로그는 날짜와 시간을 포함해야 한다.

예시:

```text
2026-06-27 08:21:28 INFO Wi-Fi disconnected
2026-06-27 08:21:28 INFO Target SSID found
2026-06-27 08:21:28 INFO Reconnect attempt
2026-06-27 08:21:30 INFO Reconnected successfully
```

로그 저장 위치:

```text
logs/wifi-auto-reconnect.log
```

# 6. 비기능 요구사항

* Windows 10/11 지원
* Python 3.12 이상 지원
* CPU 사용량 최소화
* 메모리 사용량 최소화
* 외부 의존성 최소화
* 예외 발생 시 프로그램이 종료되지 않아야 한다.
* 장시간 실행을 고려하여 안정적으로 동작해야 한다.
* 연결 상태가 일시적으로 불안정하게 조회되어도 불필요한 재접속을 최소화해야 한다.

# 9. 성공 기준

다음 조건을 만족하면 MVP를 완료한 것으로 본다.

1. 프로그램이 실행된다.
2. 설정 파일을 정상적으로 읽는다.
3. Wi-Fi가 정상 연결된 상태에서는 재접속을 시도하지 않는다.
4. 현재 연결된 SSID가 대상 SSID와 달라도, Wi-Fi가 연결되어 있으면 재접속을 시도하지 않는다.
5. Wi-Fi가 실제로 끊어진 경우 끊김을 감지한다.
6. 대상 SSID를 검색한다.
7. 대상 SSID가 발견되면 자동 재접속을 시도한다.
8. 재접속 성공 또는 실패 로그가 기록된다.
9. 재접속 중 Wi-Fi가 이미 연결된 상태로 확인되면 재시도를 중단한다.
10. 프로그램은 종료 신호를 받기 전까지 계속 백그라운드에서 실행된다.

---

# 10. 제외 범위

이번 MVP에서는 다음 기능을 구현하지 않는다.

* UI
* 트레이 아이콘
* Windows 서비스 등록
* Wi-Fi 강제 연결 해제 기능
* 특정 SSID 강제 유지 기능
* 여러 SSID 우선순위 관리
* 네트워크 품질 측정
* 인터넷 연결 확인
* 이벤트 기반 네트워크 감시

---

# 11. 구현 원칙

* 하드코딩을 최소화한다.
* 설정값은 `config.json`에서 관리한다.
* 기능별 모듈화를 유지한다.
* 예외 처리를 충분히 구현한다.
* 추후 기능 추가가 쉽도록 구조를 유지한다.
* 실제 연결 상태가 정상인 경우에는 불필요한 네트워크 조작을 하지 않는다.
